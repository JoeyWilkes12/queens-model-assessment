## 3. Irregularities and threats to validity

1. **Small fixed panels and dependent calls.** Every full four-arm panel is twelve boards × four arms, only four boards per size per arm, with one greedy observation per cell. Arms reuse boards; studies reuse the same sets. 48 calls are not 48 independent puzzle samples. Sampling rounds reuse the twelve pilot boards, so neither 72 attempts/arm nor pass@3 expands board diversity. No confidence interval based on independent calls is justified. `snapshot:studies/*/plan.json` boards, arm_names; protocols seed/temperature. No fresh3 or queue-based independent sampled fresh-board protocol exists at capture.
2. **Exploration and forking paths.** Source `docs/ollama-next-studies.md` Added 2026-11-03 and queue study notes explicitly motivate medium effort and doubled budget from observed 32k truncations and shorter Caveman traces. The original-budget studies were replaced by larger-budget panels after caps; loop-stop thresholds were calibrated after reading traces; format-recovery diagnostics were post-hoc. These are scientifically useful explorations, but not untouched confirmatory tests of Caveman. Multiple models × prompt arms × sizes × budgets × seeds × stopping policies × metrics create many potential contrasts; no multiplicity-adjusted predeclared Caveman family hypothesis was found. Frozen subsequent plans prevent within-run setting drift, but do not erase outcome-informed design selection.
3. **Caveman does not isolate a pure style effect.** Caveman is a 4,431-character/707-word system instruction; neutral is 5,007/885 and contains substantive harbor-town prose. Qwen image input per call is 1,914 neutral versus 1,984 Caveman, baseline 853, schema 911. Neutral is approximate token-length control, not exact, and its semantic distraction is another treatment. The schema arm adds answer instructions and length. Tokenizer differences change all these deltas across families. `snapshot:studies/qwen3.5-9b-nvfp4-fresh1-4arm-np32768/plan.json` arms; receipt metadata.input_tokens; arm-neutral.txt / caveman-system.txt. Do not claim equal-length controls or causally isolate terse style.
4. **Board selection after earlier exposure.** fresh1/fresh2 use deterministic first-remaining board per stratum, excluding previous local sets, but all 36 boards were in the prior public hosted frontier panel. `source:public/evidence/ollama-models/fresh1-boards.json` selection_rule/frozen_utc; fresh2-boards.json excluded_sets/pool/boards; hosted manifest and `docs/frontier-image-panel-preregistration.md`. Their disjointness is verified; “before any model saw it” and secret heldout/global nonexposure are unsupported. Fresh1 was selected after pilot outcomes, and fresh2 after fresh1 outcomes. Neither freeze is evidence of absent training exposure.
5. **Budget/model/runtime confounding.** 27B uses 24,576 tokens / 28,672 context for the safety cap; other thinking fresh-image models 32,768 / 36,864. LLaVA has 4,096 / 8,192 and think=false. Qwen4B/9B/Gemma are MLX nvfp4; 27B llama.cpp Q4_K_M; gpt-oss llama.cpp MXFP4. Architectures, tokenizers, effective parameter counts, vision encoders, boolean versus effort reasoning all differ. Gemma E4B runtime says 8.1B parameters; a tag is not controlled parameter scale. `snapshot:studies/*/plan.json` runtime.details/model_info/protocol; `source:docs/ollama-runner-features.md` probes/context cap. LLaVA's short 23–40 token outputs mean its cap did not bind, but that does not equalize reasoning opportunity.
6. **Truncation is protocol failure, not inability.** Count a capped attempt as non-strict for the fixed-budget outcome, but do not infer the model cannot solve the board. A larger budget might help, harm or change a trajectory. High65k gpt-oss has 29/48 strict, 16/48 caps, 1/48 transport failure; medium32k has 29/48 strict, 10/48 caps, 9/48 completed incorrect; high32k fresh1 has 23/48 strict, 24/48 caps, 1/48 completed incorrect. `snapshot:studies/gpt-oss-.../summary.json` rows, receipt response.done_reason. More completed output is not automatically more correct output.
7. **Greedy determinism claims fail outside specific reproduced cells.** Source runner docs claim fresh loads make answer order irrelevant and completed 32k gpt-oss outputs should reproduce at 65k. Offline full-message comparison finds **0/24 previously completed gpt-oss messages identical**, and **0/47 available exact common thinking prefixes** across 32k/65k (the remaining response is a transport error). All same-call requests retain identical message payloads, same model/digest/think/temperature/seed; num_predict and num_ctx change. Four prior strict outputs become capped; among 24 prior caps, nine become strict, twelve cap again, two are completed incorrect, one is transport failure. One additional strict gain comes from the prior completed incorrect answer. Overall strict gains/losses are 10/4, net +6. These are different runs, not “the earlier trace with more tokens”; no causal attribution of divergence solely to context is established. `FINAL-ANALYSIS.md`, `paired-gpt-oss.json` contain exhaustive pair facts; raw source/snapshot responses are keyed there. For Qwen9B historical 24k→active32k, previously documented 24/24 common thinking prefixes and 18/18 completed outputs did match; this is evidence for those specific traces only. Source selftests/20261029T201454-full/results.json checks stream_reproduces_9b_receipt (true) and stream_reproduces_4b_pilot_receipt (false, difference at char1123, 5403→7811 tokens). Repeated later selftests preserve that 4B failure; required=false means overall PASS never established universal reproducibility.
8. **Active loop-stop is outcome-dependent censoring.** Detector threshold .7 × three consecutive repeated-line checks was tuned on 102 traces; five of 28 truncations triggered and none of 74 completed calibration traces did. That is in-sample, not population specificity. Six 4B and five 9B active stops lack complete usage; counterfactual continuation unobserved. Exactly those eleven were audited; all original prefixes match and one 9B Caveman panel-7-50 escapes to strict at 29,094 tokens. Outcome selection precludes representative detector-validation rates. `source:public/evidence/ollama-models/loop-audit.json`; source docs/ollama-loop-stop-analysis-2026-10-30.md; snapshot selected audit plan.audit_calls and receipt metadata.audit. New shadow studies preserve outcomes, and fresh2 gpt-oss now has 16 flags including five strict escapes (previous Nov6 subset six/two). High65k has 12 flags/two strict escapes; medium has five/one. Do not treat triggers as hopeless loops or estimate exact saved tokens from characters/chunks. Later full selftests' loop_audit_no_false_positives required check remains false; an overall failed full selftest is not silently equivalent to all checks passed.
9. **Deadline, interruptions and denominators.** Nov6→7 session records deadline for high65k; Nov7→8 contains calls but no final queue result; baseline_panel-9-45 started-only directory is moved under abandoned/ at 2026-11-09T06:00:26.470163+00:00 with reason “started without a recorded result (interrupted session)”. Nov8 23:00 session records its replacement successfully. Preserve operational attempt history, but count only 48 completed outcome records once, not 49 accuracy trials; elapsed/request totals exclude the abandoned attempt and are therefore not full job resource totals. `source:.../gpt-oss-20b-fresh1-text-4arm-np65536/abandoned/baseline_panel-9-45_20261108T230026/abandoned.json` and contents; source sessions 20261106T230000/20261107T225602/20261108T230006.json. Nov9/10 are idle; completion labels alone could misclassify Nov7.
10. **Recorded stream failure has unknown spend/usage.** 65k neutral_panel-9-45 response.error is type=stream_error, message=prediction aborted, token repeat limit reached; metadata has response_origin=client_exception, http_status/returned_model/done/finish_reason/input_tokens/output_tokens all null, elapsed_seconds=1488.2632926250008. No final content retained. Strict false and diagnostic false correctly regrade with None. This is neither a token-cap outcome nor completed puzzle error. Its presence does not make the 48-record plan incomplete; it makes actual final-answer coverage 47/48. No retry replaced this recorded failure. Output/input totals are known subtotals on 47 calls, and full condition/neutral-arm cost unknown. Resource guard's last_llama_server_decode.tokens is not a replacement for terminal usage. Exact request/response hashes verify. Public importer narrowly supports this record without fabricating response identity.
11. **Memory gates, runner drift and missingness.** 27B sampling r2 was deferred on Oct31→Nov1 for memory_gate, then finished Nov1→2; fresh1 27B spans multiple nights and runner versions. Its call-time script hashes are tabulated in section1; some old frozen study summaries refresh timestamps on idle checks without new calls. Admission and retries change scheduling/host conditions and can select which calls are observed before deadline. Preserve partial historical 9B/27B conditions (6/24,2/24; 40 unrecorded); do not impute missing as failures or re-run them automatically. `source:sessions/20261031T230005.json`, next session results; all summary rows; `source:docs/ollama-runner-features.md` §§7,9. The newer anonymous-memory gate is not the exact earlier active-memory-only rule.
12. **Version/provenance limits.** All frozen plans inspected report server_version=0.40.10; saved full selftests report that version and auto-update disabled. No evidence of Ollama version drift was found in saved records, but a current live version check is deliberately out of scope. Across 835 primary/audit metadata: 102 lack runner blocks, 491 have null git_commit, 242 use runner-versions.json attribution. Backfill maps hashes to commits with backfilled=true, not contemporaneous verified checkout facts. All known runner hashes match mapping entries; source HEAD and dirty status are capture facts. Do not overwrite receipt nulls, or treat historical scripts_uncommitted=false as verified clean when Git failed under launchd. `source:.../runner-versions.json` versions; receipt metadata.runner; source docs §8.
13. **Host and timing uncertainty.** Request elapsed_seconds includes measured request processing, but excludes separate placement/admission, quiet waits, overnight idle gaps and abandoned work. Token-weighted decode throughput excludes loading/prefill. Source docs describe post-27B slowdown and crash/memory history; numeric host windows can include the previously loaded model. Temperature/thermal causation is UNCONFIRMED: saved pressure/throughput and chronology do not isolate thermal effects on answer outcomes; no random host assignment or common controlled thermal baseline. 65k transport failure guard not tripped does not prove no runtime instability. `source:docs/ollama-observations-2026-10-29.md`, docs/ollama-lessons.md; metadata.resource_guard and host.json window; public host-summary.json. Never sum inter-night calendar spans as model run time or attribute max VRAM in a mixed window solely to the current model.
14. **Grades, rescues and exclusions.** Strict JSON + puzzle-rule checking is primary; grader.diagnose can extract a JSON object from surrounding text. Importer format_only_correct is separately conservative and additionally accepts a whole bare array only when unambiguous; one sampled9B answer has source outcome incorrect but conservative format-only true. Neither diagnostic changes strict. Thirty-eight rescues are distinct 256-token assisted continuation requests replaying thinking with an early-stop instruction and prefix; 4B/9B active canceled totals remain unknown. Probes/selftests/runtime failures (e.g. mllama architecture load rejection) are not zero-scoring model panels. Targeted audit unused scaffold rows are excluded, not missing. `scripts/llm_panel/grading.py:1–69`; `scripts/ollama/import_studies.py` format_only_correct/validate_rescue; each rescue metadata; source docs runner features/probes.
15. **Local cost model assumptions.** Provider fee zero does not mean total computation cost zero. Electricity, amortized hardware and local opportunity costs are unmeasured. Saved Oct30 OpenRouter Qwen rates price reported local token usage; hosted quantization/runtime/tokenizer/cache/image accounting may differ. 4B uses a proxy listing, not exact 4B model tariff. No saved gpt-oss/Gemma/LLaVA price exists; do not invent a rate. Thinking counted once as output, replay input fully charged, failures/caps retained in spend denominator; missing terminal usage makes full cost unknown, zero strict makes cost per success undefined. `public/evidence/local-qwen-pricing.json`; `src/localQwenMath.ts` estimateCohort/compareArms; docs/local-qwen-costs.md.
